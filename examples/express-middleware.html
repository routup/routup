Express Middleware ​

A Node.js (req, res, next) middleware that sets an X-Request-Id header, wrapped with fromNodeMiddleware and placed in front of a routup route. The middleware is hand-written here; an Express middleware from npm, such as cors(), is wrapped the same way.

ts
import { randomUUID } from 'node:crypto';
import type { IncomingMessage, ServerResponse } from 'node:http';
import { App, defineCoreHandler, fromNodeMiddleware } from 'routup';

function requestId(_req: IncomingMessage, res: ServerResponse, next: (err?: unknown) => void) {
    res.setHeader('X-Request-Id', randomUUID());
    next();
}

export const app = new App();

app.use(fromNodeMiddleware(requestId));

app.get('/', defineCoreHandler(() => 'Hello'));

Try It ​

Install routup, serve the app from a second file and start it with Node.js:

typescript
import { serve } from 'routup';
import { app } from './app.ts';

serve(app, { port: 3000 });
bash
curl -i http://localhost:3000/
# HTTP/1.1 200
# X-Request-Id: e58fa4b8-e24e-4236-903d-24abe7f1d1e6
# content-type: text/plain; charset=utf-8
# ...
#
# Hello

The id is a new UUID on every request.

How It Works ​

  • fromNodeMiddleware calls the middleware with the Node.js req and res of the server and bridges its next() callback into the pipeline. See Express Compatibility.
  • A header set with res.setHeader() is sent together with the response that the routup handler returns.
  • The wrapper needs a Node.js server, so the app answers 500 under app.fetch() with a plain Request. See How it Works for the requirement and how to test such an app, and Limitations for the limits of the bridge.
